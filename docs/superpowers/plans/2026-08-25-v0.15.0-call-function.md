# v0.15.0 — `call_function()` (custom `fn::` stored functions) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen: inline,
> task-level checkpoints) to implement this plan task-by-task. Steps use checkbox (`- [ ]`)
> syntax. Use superpowers:test-driven-development within each task and
> superpowers:systematic-debugging on any failure.

**Goal:** Invoke a server-side function declared with `DEFINE FUNCTION fn::…` and get its
return value back in Python, with arguments **bound** as query parameters, named arguments
resolved against the declared signature, the value optionally coerced to a type, SDK errors
wrapped in the ORM hierarchy, and correct behaviour inside both transaction strategies.

**Architecture:** `functions.py` gains three **pure** helpers (name normalisation/validation,
`DEFINE FUNCTION` text → ordered parameter names, statement building) — it imports nothing from
the package, so it stays cycle-free. `connection_manager.py` gains the async `call_function()`,
the per-`(namespace, database)` signature cache, and cache reset on `unset_connection()`.
`model_base.py` gains a thin delegating classmethod. No new SDK surface: SDK 2.0.0 has **no**
`run()`/`call()` method, so the call goes through `client.query()` — or through
`Transaction.add()` when a `tx=` is open.

**Tech Stack:** Python 3.11+, Pydantic v2, `surrealdb[pydantic]>=2.0.0,<3.0.0`, pytest +
pytest-asyncio. Dual-DB test harness: SurrealDB 3.2.4 (:8001) and 2.6.5 (:8002).

**Design spec:** `docs/superpowers/specs/2026-08-25-v0.15.0-call-function-design.md`

## Global Constraints

- **Official SDK only** (`surrealdb[pydantic]>=2.0.0,<3.0.0`). No custom SDK, no
  `import surrealdb` outside `_sdk.py`.
- **The bare call form is mandatory.** The ORM emits `fn::name($_fnarg0);` — **never**
  `RETURN fn::name(…)`. A `RETURN` inside a `BEGIN … COMMIT` batch terminates the transaction
  early and silently on **both** DB lines (see the spec's finding table): the statement queued
  after it is reported `status: OK` and never executes. Task 5 carries the regression test.
- **Both DB lines stay green.** The call itself is identical on 2.6.5 and 3.2.4 — verified by
  probe on :8001, :8002 **and** :8003. The only `pytest.skip` in this feature is the
  interactive-transaction test (3.x + WebSocket only), which reuses the existing
  `tx.is_interactive` gate.
- **Never assert on server error wording.** A missing function reads
  `Function 'fn::x' not found: …` on 3.x and `The function 'fn::x' does not exist` on 2.6.x.
  Tests assert on the ORM's exception **type**.
- **Prerequisite:** `bash .claude/skills/orm-light-feature/scripts/start_test_dbs.sh`
  (3.2.4 → :8001, 2.6.5 → :8002, 3.1.5 → :8003).

## Task 1: Pure helpers — name validation, signature parsing, statement building

**Files:** `src/surreal_orm_lite/functions.py`, `tests/test_call_function.py`

- [ ] **Step 1 — Write the failing tests.** In `tests/test_call_function.py`, class
      `TestFunctionNameNormalisation`, `TestSignatureParsing`, `TestCallStatementBuilding`:
  - `normalize_function_name("greet") == "fn::greet"`; `"fn::greet"` is idempotent.
  - Nested namespaces survive: `"fn::billing::total"`, `"billing::total"` → `"fn::billing::total"`.
  - `ValueError` for `""`, `"fn::"`, `"fn::x; DROP TABLE user"`, `"fn::x()"`, `"fn::1bad"`,
    `"fn::a::"`, `"fn::a b"`, and a non-string argument (`TypeError`).
  - `parse_function_parameters("DEFINE FUNCTION fn::greet($name: string, $times: int) { … } PERMISSIONS FULL")`
    `== ("name", "times")`; zero-arg → `()`; a `TYPE` clause containing a comma
    (`$opts: option<array<string>>`) does not split wrongly; the 2.6.x variant (trailing `;`
    inside the body) parses identically.
  - `build_call_statement("fn::greet", ["ada", 3])` → `("fn::greet($_fnarg0, $_fnarg1);",
{"_fnarg0": "ada", "_fnarg1": 3})`; zero args → `("fn::noargs();", {})`.
  - **The statement never contains a `RETURN`** (assert `"RETURN" not in statement`) and never
    contains an argument's _value_ (pass `");DELETE user;--"` and assert it appears only in the
    variables dict).
- [ ] **Step 2 — Run, expect FAIL** (`ImportError`).
- [ ] **Step 3 — Implement** in `functions.py`. Reuse the module's existing
      `VALID_VARIABLE_NAME`-style identifier regex for each `::`-separated segment. Parse the
      parameter list by taking the text between the first `(` and its matching `)` after the
      function name, then reading each `$ident` at depth 0 — this is why a `TYPE` clause with
      commas or angle brackets is safe.
- [ ] **Step 4 — Run on both ports**, expect PASS (these are pure unit tests; both ports must
      still be green):
      `bash .claude/skills/orm-light-feature/scripts/dual_db_test.sh -k call_function`
- [ ] **Step 5 — Lint + commit**: `feat(call-function): pure helpers for name, signature and statement`

## Task 4: `params=` named arguments + signature cache

**Files:** `src/surreal_orm_lite/connection_manager.py`, `tests/test_call_function.py`

- [ ] **Step 1 — Write the failing tests.** Class `TestCallFunctionNamedParamsE2E`:
  - `params={"b": 2, "a": 1}` on `fn::cf_sum($a, $b)` returns the same value as `args=[1, 2]`
    — i.e. **dict order is irrelevant**, declaration order wins;
  - passing both `args` and `params` raises `ValueError`;
  - an unknown key and a missing key each raise `ValueError` **naming the expected parameters**;
  - the signature is cached: a second call with `params=` issues no second `INFO FOR DB`
    (count queries through a spy);
  - a function **redefined** with a new parameter list resolves after one automatic cache
    refresh rather than failing;
  - `params={}` on a zero-argument function works;
  - `params=` for a nonexistent function raises `SurrealDbNotFoundError`;
  - `unset_connection()` clears the cache (a unit test on the class attribute).
- [ ] **Step 2 — Run, expect FAIL.**
- [ ] **Step 3 — Implement** `_resolve_named_args()`: read `INFO FOR DB`, take `functions[name
    without fn:: prefix]`, `parse_function_parameters()`, cache under
      `(namespace, database, name)`. On a key mismatch, invalidate that entry, re-read **once**,
      and only then raise. **The signature read always goes through `client.query()` directly,
      never through `tx`** — buffered transactions forbid reads, and this makes `params=` work
      inside one. Clear the cache in `unset_connection()`.
- [ ] **Step 4 — Run on both ports**, expect PASS.
- [ ] **Step 5 — Lint + commit**: `feat(call-function): resolve named params from the declared signature`

## Task 5: `tx=` — both transaction strategies, and the `RETURN` regression guard

**Files:** `src/surreal_orm_lite/connection_manager.py`, `tests/test_call_function.py`

- [ ] **Step 1 — Write the failing tests.** Class `TestCallFunctionTransactionE2E`, using a
      mutating fixture function (`fn::cf_bump($by: int)` doing `UPDATE cf_ctr:a SET n += $by`):
  - **both lines** — the function's write lands after the transaction commits;
  - **both lines** — a statement queued **after** the call still executes. This is the
    regression guard for the `RETURN`-aborts-a-batch finding: inside one `transaction()`, call
    the function and then `save()` a model, and assert **both** the counter bumped **and** the
    record exists. This test would fail if anyone reintroduces `RETURN`;
  - **both lines** — the function's write is rolled back when the body raises;
  - interactive only (`if not tx.is_interactive: pytest.skip(...)`) — the call returns the
    function's value inside the transaction;
  - buffered only (skip when `tx.is_interactive`) — the call returns `None`;
  - `return_type=` with a buffered `tx=` raises `ValueError` (there is no value to coerce);
    assert it only on the buffered strategy.
- [ ] **Step 2 — Run, expect FAIL.**
- [ ] **Step 3 — Implement**: when `tx` is given, route through `await tx.add(stmt, vars)`
      instead of `client.query()`. `BufferedTransaction.add()` returns `None`;
      `InteractiveTransaction.add()` returns the statement's result. Raise `ValueError` for
      `return_type` + a non-interactive `tx` **before** queuing anything. Coerce only when a
      value actually came back.
- [ ] **Step 4 — Run on both ports**, expect PASS (2.6.5 skips the interactive-only cases,
      8001 skips the buffered-only ones — never a failure).
- [ ] **Step 5 — Lint + commit**: `feat(call-function): run stored functions inside a transaction`
