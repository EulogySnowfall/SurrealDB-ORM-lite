# v0.16.0 — Connection-level authentication — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (chosen: inline,
> task-level checkpoints) to implement this plan task-by-task. Steps use checkbox (`- [ ]`)
> syntax. Use superpowers:test-driven-development within each task and
> superpowers:systematic-debugging on any failure.

**Goal:** Authenticate the ORM's connection as a SurrealDB **record user** or as a different
**system user**, keep that identity across reconnects and event loops, read back who is
authenticated, and normalize the SDK's per-DB-line authentication errors into one ORM
exception.

**Architecture:** a new `auth.py` holds the **pure**, I/O-free pieces — the `AuthTokens`
dataclass, `build_auth_payload()` (credentials → SDK payload, with all argument validation) and
`wrap_auth_error()`. It imports only `exceptions.py`, so it stays cycle-free, and it is the
module v0.17.0's `AuthenticatedUserMixin` will extend. `connection_manager.py` gains the five
async classmethods, the `__session_token` slot, the token replay inside `get_client()`, and two
introspection helpers. No new SDK surface is invented: all five primitives are native on both
the WebSocket and HTTP connection classes.

**Tech Stack:** Python 3.11+, Pydantic v2, `surrealdb[pydantic]>=2.0.0,<3.0.0`, pytest +
pytest-asyncio. Dual-DB test harness: SurrealDB 3.2.4 (:8001) and 2.6.5 (:8002).

**Design spec:** `docs/superpowers/specs/2026-08-29-v0.16.0-connection-auth-design.md`

## Global Constraints

- **Official SDK only** (`surrealdb[pydantic]>=2.0.0,<3.0.0`). No custom SDK, no
  `import surrealdb` outside `_sdk.py`.
- **Both DB lines stay green.** The five methods behave identically on 2.6.5 and 3.2.4. The
  only `pytest.skip` in this feature is the refresh-token test: `DEFINE ACCESS … WITH REFRESH`
  does not parse on 2.6.x, so the test probes it and skips.
- **Never assert on server error wording.** The same wrong password raises `NotFoundError` on
  3.x and `InternalError` on 2.6.x, and a malformed token raises a client-side `ValueError` on
  both. Tests assert on the ORM's exception **type**.
- **Never let a JWT reach a log, a repr or an assertion diff.** `AuthTokens.__repr__` redacts;
  tests assert on `bool(tokens.access)` and on absence from `repr()`, never on the token value.
- **Every E2E row uses a unique identifier.** A duplicate signin identifier makes 2.6.x fail
  with `No record was returned` while 3.x succeeds — a genuine source of order-dependent
  flakiness (issue #160's lesson). Derive the identifier from `uuid4()` per test.
- **Test tables must grant the record user `select` on itself**
  (`PERMISSIONS FOR select, update WHERE id = $auth.id`), otherwise `info()` silently returns
  `None`. One test asserts that `None` on purpose; every other test needs the permission.
- **Prerequisite:** `bash .claude/skills/orm-light-feature/scripts/start_test_dbs.sh`
  (3.2.4 → :8001, 2.6.5 → :8002, 3.1.5 → :8003).

  (CI lints `tests/` too).

## Task 1: Pure layer — `AuthTokens`, payload building, error wrapping

**Files:** `src/surreal_orm_lite/auth.py`, `src/surreal_orm_lite/exceptions.py`,
`tests/test_auth.py`

- [ ] **Step 1 — Write the failing tests.** In `tests/test_auth.py`, classes `TestAuthTokens`,
      `TestBuildAuthPayload`, `TestWrapAuthError`:
  - `AuthTokens("jwt", "refresh")` exposes `.access` / `.refresh`; `refresh` defaults to `None`;
    the instance is frozen (assigning raises).
  - **`repr()` contains neither token value** and mentions `<redacted>`; `AuthTokens` defines no
    `__str__` that returns the JWT (`str(tokens)` must not equal `tokens.access`).
  - Record payload: `build_auth_payload(access="acct", variables={"email": "a"},
default_namespace="ns", default_database="db")` → `{"namespace": "ns", "database": "db",
"access": "acct", "variables": {"email": "a"}}`.
  - Explicit `namespace=`/`database=` override the defaults.
  - System-user payload: `build_auth_payload(username="root", password="root",
default_namespace="ns", default_database="db")` → `{"username": "root", "password": "root"}` —
    **no `namespace`, no `database`** (injecting them turns a root signin into a DB-user signin,
    which fails).
  - A system user **with** an explicit `namespace=` (and optionally `database=`) includes them.
  - Refresh payload: `build_auth_payload(access="acct", refresh="surreal-refresh-x",
default_namespace="ns", default_database="db")` → `{"namespace": "ns", "database": "db",
"access": "acct", "refresh": "surreal-refresh-x"}` — the key sits at **top level**, never
    inside `variables` (the server rejects that with `NotAllowedError`).
  - `ValueError` for: no shape at all; two shapes mixed; `access=` with neither `variables=`
    nor `refresh=`; `variables=` together with `refresh=`; `refresh=` without `access=`;
    `username=` without `password=`; `password=` without `username=`; `database=` without
    `namespace=`; record access when no namespace/database is available at all.
  - `wrap_auth_error(exc, "signin")` returns a `SurrealDbAuthenticationError` for an SDK
    `ValueError`, a generic `Exception`, and an ORM `SurrealDbError`; the message names the
    operation; the result is an instance of `SurrealDbError` (so existing handlers catch it).
- [ ] **Step 2 — Run, expect FAIL** (`ModuleNotFoundError: surreal_orm_lite.auth`).
- [ ] **Step 3 — Implement.** Add `SurrealDbAuthenticationError(SurrealDbError)` to
      `exceptions.py` with a docstring stating it covers every authentication failure on both DB
      lines. Write `auth.py`: `AuthTokens` as `@dataclass(frozen=True, slots=True)` with a
      hand-written `__repr__`; `build_auth_payload()` doing all validation **before** any I/O;
      `wrap_auth_error()` mapping unconditionally (no substring matching — these calls do
      nothing but authenticate, so any failure is an auth failure).
- [ ] **Step 4 — Run on both ports**, expect PASS (pure unit tests, both ports must stay green):
      `bash .claude/skills/orm-light-feature/scripts/dual_db_test.sh -k auth`

## Task 5: Session persistence — replay the token in `get_client()`

**Files:** `src/surreal_orm_lite/connection_manager.py`, `tests/test_auth.py`

- [ ] **Step 1 — Write the failing tests.** Class `TestSessionPersistenceE2E`:
  - after a record `signin()`, `await SurrealDBConnectionManager.reconnect()` then `info()`
    reports the **same** record — the ORM did not silently fall back to root;
  - the same holds after `close_connection()` drops the cached client and the next
    `get_client()` rebuilds it;
  - a **dead** stored token (sign in, then have a second root client
    `REMOVE ACCESS`/`DELETE` the record so the token no longer resolves, or feed a
    hand-crafted expired JWT) makes the next `get_client()` raise
    `SurrealDbAuthenticationError` — **not** `SurrealDbConnectionError` — clear the stored
    token, and leave the connection usable: the very next `get_client()` succeeds at the
    configured identity.
- [ ] **Step 2 — Run, expect FAIL** (reconnect currently reverts to root).
- [ ] **Step 3 — Implement.** In `get_client()`, after the client is cached and **outside** the
      existing broad `try/except` that maps everything to `SurrealDbConnectionError`, replay
      `authenticate(stored_token)`. On failure: drop the stored token, keep the cached client,
      raise `SurrealDbAuthenticationError`. Comment why the replay sits outside the `except` —
      the connection is fine, only the identity is gone, and collapsing the two would send
      callers chasing a network problem that does not exist.
- [ ] **Step 4 — Run on both ports**, expect PASS.

## Task 6: Refresh tokens — exchange and rotation (3.x only)

**Files:** `src/surreal_orm_lite/connection_manager.py`, `tests/test_auth.py`

- [ ] **Step 1 — Write the failing tests.** Class `TestRefreshTokenE2E`, gated by a
      module-level `_supports_refresh(client)` helper that attempts
      `DEFINE ACCESS … TYPE RECORD … WITH REFRESH DURATION FOR TOKEN 15m, FOR SESSION 12h,
FOR GRANT 30d` and returns `False` when it fails to parse — `pytest.skip("WITH REFRESH
requires SurrealDB 3.x")` on 2.6.x, the same adaptive-skip shape v0.9.0 uses for interactive
      transactions:
  - `signup()` against a `WITH REFRESH` access method yields a non-empty `tokens.refresh`,
    while an access method **without** `WITH REFRESH` yields `refresh is None`.
  - `signin(access=…, refresh=tokens.refresh)` returns a fresh pair and restores the **same**
    `$auth` record.
  - **Rotation**: the returned `refresh` differs from the one spent, and re-using the spent one
    raises `SurrealDbAuthenticationError`.
  - With `store=True`, `get_session_token()` **and** `get_refresh_token()` are both replaced by
    the new pair; with `store=False` neither changes.
  - A bogus refresh token raises `SurrealDbAuthenticationError`.
- [ ] **Step 2 — Run, expect FAIL** (`TypeError: unexpected keyword argument 'refresh'`).
- [ ] **Step 3 — Implement**: thread `refresh=` through `signin()` into `build_auth_payload()`
      (Task 1 already validates it), store `tokens.refresh` alongside the access token when
      `store=True`, and add `get_refresh_token()`. The `signin()` docstring carries the
      rotation warning in the strongest terms — a spent refresh token is dead immediately, and
      an application that fails to persist the new one logs its user out permanently with no
      error at the call site. Clear the refresh slot in `invalidate()` and
      `unset_connection()` alongside the access token.
- [ ] **Step 4 — Run on both ports**: PASS on 8001, **SKIPPED** on 8002 (assert the skip is
      reported, not a failure).
- [ ] **Step 5 — Lint + commit**: `feat(auth): exchange refresh tokens for a new session (3.x)`
