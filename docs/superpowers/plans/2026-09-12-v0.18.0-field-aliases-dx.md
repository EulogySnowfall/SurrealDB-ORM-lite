# v0.18.0 — Field aliases, `server_fields` & `merge(refresh=False)` — Implementation plan

> Design: [`2026-09-12-v0.18.0-field-aliases-dx-design.md`](../specs/2026-09-12-v0.18.0-field-aliases-dx-design.md)
> Branch: `feature/v0.18.0-field-aliases-dx` · Tests: `tests/test_aliases_dx.py`
> Every task is TDD (failing test → implement → green) and verified on **8001 (3.2.x) and
> 8002 (2.6.x)** with `scripts/dual_db_test.sh -k <pattern>`, then `ruff format` + `ruff check`,
> then one Conventional Commit.

## Task 1 — Alias mapping primitives on `BaseSurrealModel`

- [ ] Test: `get_field_aliases()` returns `{python: column}` for aliased fields only, `{}` for a
      plain model; inherited aliases are included; `to_db_field` / `to_py_field` round-trip and
      pass through unknown names; both translate only the first segment of a dotted path.
- [ ] Implement the three classmethods in `model_base.py`, backed by a per-class cache keyed on
      `cls` (built lazily from `cls.model_fields[…].alias`, so it is correct after Pydantic has
      finished building the model — unlike `__init_subclass__`).
- [ ] Add `model_config = ConfigDict(populate_by_name=True)` to `BaseSurrealModel`; test that an
      aliased field accepts **both** names at construction.
- [ ] Commit: `feat(model): alias mapping primitives + populate_by_name (v0.18.0)`

## Task 2 — `server_fields` config & accessor

- [ ] Test: `get_server_fields()` merges `model_config["server_fields"]` with computed fields;
      returns a `frozenset`; `{}`/absent config yields just the computed set; an entry naming an
      undeclared field raises `ValueError` naming it; a subclass inherits the parent's config.
- [ ] Add `server_fields: list[str] | None` to `SurrealConfigDict` (with docstring entry) and
      implement `get_server_fields()` in `model_base.py`.
- [ ] Commit: `feat(model): server_fields config and accessor (v0.18.0)`

## Task 3 — Write payload honours aliases and `server_fields`

- [ ] Test (unit): `_write_payload()` emits column keys and omits `id`, computed fields **and**
      `server_fields`.
- [ ] Test (E2E, both ports): `save()` on an aliased model stores the column — verified by a raw
      `client.query("SELECT * FROM …")` showing `password_hash`, not `password`; a
      `server_fields` column set by a `DEFINE FIELD … VALUE $before OR time::now()` survives a
      `save()`/`update()` instead of being nulled.
- [ ] Implement: `_write_payload()` → `model_dump(by_alias=True, exclude={"id", *get_server_fields()})`.
- [ ] Commit: `feat(model): write payloads use aliases and skip server_fields (v0.18.0)`

## Task 4 — Hydration honours aliases (reads + returned rows)

- [ ] Test (unit): `_apply_record({"password_hash": "x"})` sets `.password`; `only=` is matched
      on Python names; an unknown column is ignored as before.
- [ ] Test (E2E, both ports): `refresh()` and `objects().exec()` hydrate an aliased model; the
      computed/`server_fields` columns are populated on the instance straight after `save()`.
- [ ] Implement: translate column → Python in `_apply_record`; replace the ad-hoc hydration loops
      in `_do_save` (both branches) and `refresh()` (both branches) with `_apply_record` calls so
      the rule lives in one place.
- [ ] Commit: `feat(model): hydrate aliased columns onto Python attributes (v0.18.0)`

## Task 5 — `merge()` / `server_values` write through aliases

- [ ] Test (unit): `merge(password="x")` sends `{"password_hash": "x"}` while setting `.password`
      locally; `server_values={"display": SurrealFunc(...)}` compiles `display_name = …`.
- [ ] Test (E2E, both ports): `merge()` and `merge(server_values=)` on an aliased field update
      the right column and leave the instance consistent.
- [ ] Implement: translate keys in `merge()`'s wire payload, in `_merge_server`, and in
      `_do_save_server`; keep the local-apply loops on Python names.
- [ ] Commit: `feat(model): merge and server_values address aliased columns (v0.18.0)`

## Task 6 — QuerySet & `Q` honour aliases

- [ ] Test (unit): compiled SQL for `filter(password="x")`, `Q(password="x")`, `order_by("-password")`,
      `values("password")`, `fetch("author")`, `sum("password")`-style helpers and
      `bulk_update(password="x")` all name the column.
- [ ] Test (E2E, both ports): filter + order_by + bulk_update round-trip on an aliased model.
- [ ] Implement: `Q.to_sql(…, field_map=None)` (recursive), and translation at each QuerySet
      boundary listed in the design's §5 table.
- [ ] Commit: `feat(queryset): translate aliased field names in filters and clauses (v0.18.0)`

## Task 7 — `merge(refresh=False)`

- [ ] Test (unit): with `refresh=False` no second query is issued (patched client), `data` lands
      on the instance, and the `server_values` statement ends with `RETURN NONE`.
- [ ] Test (E2E, both ports): `merge(..., refresh=False)` persists; a follow-up `refresh()` shows
      the value; the default `refresh=True` behaviour is unchanged.
- [ ] Implement: `refresh: bool = True` parameter threaded through `merge()`, `_merge_server`
      (adding `RETURN NONE`) and the interactive-tx branch.
- [ ] Commit: `feat(model): merge(refresh=False) skips the resync round-trip (v0.18.0)`

## Task 8 — Guards: computed vs server field

- [ ] Test: an explicit write to a computed field still raises; the same write to a
      `server_fields` entry succeeds (`merge`, `bulk_update`, `server_values`).
- [ ] Implement whatever guard adjustment the tests expose (expected: none beyond keeping
      `_reject_computed_writes` computed-only now that `get_server_fields()` is a superset).
- [ ] Commit: `test(model): pin the computed-vs-server_fields write contract (v0.18.0)`
