# v0.17.0 — Model-level authentication (`AuthenticatedUserMixin`) — Design

- **Date**: 2026-09-11
- **Status**: Approved (design)
- **Target version**: 0.17.0
- **Roadmap**: Tier 1, Phase C — Auth & DX
- **SDK primitives**: native — `client.signup()`, `client.signin()`, `client.authenticate()`,
  `client.info()`, plus `AsyncSurreal(url)` / `connect()` / `use()` / `close()` to build the
  short-lived connection each call runs on. The `DEFINE ACCESS` / `DEFINE TABLE` statements go
  through `client.query()`, as all DDL does.
- **Constraint**: official SDK only (`surrealdb[pydantic]>=2.0.0,<3.0.0`); all SDK imports via
  `_sdk.py`.

## Goal

Turn v0.16.0's connection-level auth into a **model-level** one: declare a user model, let the
ORM generate its `DEFINE ACCESS` statement, and get a **hydrated model instance** back from
signup and signin — without the auth call silently re-identifying the connection every other
model shares.

```python
from surreal_orm_lite import AuthenticatedUserMixin, BaseSurrealModel, SurrealConfigDict


class User(AuthenticatedUserMixin, BaseSurrealModel):
    model_config = SurrealConfigDict(
        primary_key="email",
        access_name="account",
        identifier_field="email",
        password_field="password",
    )

    email: str
    password: str
    name: str = ""


# Once, at start-up: DEFINE TABLE user … PERMISSIONS + DEFINE ACCESS account …
await User.define_access()

# Register — returns the User instance, not a bare token
result = await User.signup(email="ada@example.com", password="s3cret", name="Ada")
result.user       # User instance, hydrated from the record the server created
result.tokens     # AuthTokens — the v0.16.0 container, redacting repr

# Authenticate an existing one
result = await User.signin(email="ada@example.com", password="s3cret")

# A later request carrying the stored JWT: token → current user
me = await User.authenticate(result.tokens.access)

# Renew without the password — SurrealDB 3.x only, and the refresh token ROTATES
result = await User.refresh(stored_refresh)
```

The headline difference from v0.16.0: **every call above runs on its own short-lived
connection**. The process-wide client keeps the identity `set_connection()` gave it, so a web
application can authenticate concurrent users without them trampling each other — the exact
footgun v0.16.0's docstrings warn about at length.

## SDK primitives used

| Need                       | Primitive                                         | Notes                                           |
| -------------------------- | ------------------------------------------------- | ----------------------------------------------- |
| Build an isolated session  | `AsyncSurreal(url)` + `connect()` + `use(ns, db)` | `connect()` only for `ws://` / `wss://`         |
| Register a record user     | `client.signup(payload)`                          | payload built by v0.16.0's `build_auth_payload` |
| Authenticate a record user | `client.signin(payload)`                          | idem                                            |
| Re-attach a stored JWT     | `client.authenticate(token)`                      | idem                                            |
| Read back the record       | `client.info()`                                   | returns the full record as a `dict`             |
| Emit the access DDL        | `client.query(statement, {})`                     | `DEFINE TABLE` + `DEFINE ACCESS`                |
| Release the session        | `client.close()`                                  | best-effort, suppressed                         |

No new SDK surface is needed: v0.16.0 already proved all five auth methods exist on both the
WebSocket and HTTP connection classes.

### Empirical facts, probed on :8001 (3.2.4) and :8002 (2.6.5)

Measured before this spec was written, not assumed. **All findings are identical on both
lines** unless stated.

1. **A fresh client can sign up and sign in with no prior root signin.** Connect, `use(ns, db)`,
   then `signup(...)` succeeds straight from an anonymous session. This is what makes the
   ephemeral design possible at all — the short-lived client never needs the root credentials.
2. **`info()` returns the complete record as a `dict`**, including `id` as a `RecordID`. So
   `cls.from_db(record)` hydrates an instance directly, with no extra `SELECT`.
3. **`info()` also returns the password hash** — `password` comes back as
   `$argon2id$v=19$m=…`, never the plaintext. A hydrated instance therefore carries the hash in
   its password field. This is SurrealDB's behaviour, not something the ORM chooses, and it is
   documented rather than hidden: silently blanking a field the server did return would be a
   worse surprise than the hash itself.
4. **`authenticate(jwt)` on a brand-new client fully restores the record identity** — a
   subsequent `info()` returns the same record. This is what lets `User.authenticate(token)`
   work per-request with no server-side session affinity.
5. **The isolation claim holds.** After a full ephemeral signup + signin + authenticate cycle,
   the separate root client still answers `INFO FOR DB;` — it never lost its powers. Its
   `info()` returns `None`, which is correct: a root user is not a record.
6. **One DDL string works on both lines.** The same `DEFINE TABLE OVERWRITE … PERMISSIONS` +
   `DEFINE ACCESS OVERWRITE … TYPE RECORD` with `crypto::argon2::generate` / `compare` applies
   cleanly to 3.2.4 and 2.6.5 alike. Only `WITH REFRESH` differs (see dispatch below).

## Capability dispatch (3.x vs 2.6.x)

| Surface                                                    | 2.6.x                    | 3.x                      |
| ---------------------------------------------------------- | ------------------------ | ------------------------ |
| `access_ddl()`, `define_access()` (without `with_refresh`) | same                     | same                     |
| `signup()`, `signin()`, `authenticate()`                   | same                     | same                     |
| `AuthResult.tokens.refresh`                                | always `None`            | set under `WITH REFRESH` |
| `with_refresh=True` in the model config                    | `define_access()` raises | supported                |
| `refresh()`                                                | raises, clear message    | supported                |

There is **no runtime probe**. `access_ddl()` is a pure string renderer, so it emits the
`WITH REFRESH` clause on both lines; the server is the one that rejects it, and
`define_access()` surfaces that as a `SurrealDbAuthenticationError` naming the 3.x requirement
rather than a raw parse error. The E2E tests for the refresh path `pytest.skip()` on 2.6.x,
exactly as v0.16.0's do.

## Public API

```python
# model_auth.py — new module

@dataclass(frozen=True, slots=True)
class AuthResult(Generic[_M]):
    """The model instance plus the tokens the server issued for it."""
    user: _M
    tokens: AuthTokens
    # repr delegates redaction to AuthTokens: no JWT reaches a log or an assertion diff.


class AuthenticatedUserMixin:
    @classmethod
    def get_access_name(cls) -> str: ...
    @classmethod
    def access_ddl(cls, *, overwrite: bool = True, with_table: bool = True) -> list[str]: ...
    @classmethod
    async def define_access(cls, *, overwrite: bool = True, with_table: bool = True,
                            tx: Transaction | None = None) -> None: ...

    @classmethod
    async def signup(cls, *, bind: bool = False, **fields: Any) -> "AuthResult[Self]": ...
    @classmethod
    async def signin(cls, *, bind: bool = False, **credentials: Any) -> "AuthResult[Self]": ...
    @classmethod
    async def authenticate(cls, token: str, *, bind: bool = False) -> Self: ...
    @classmethod
    async def refresh(cls, refresh_token: str, *, bind: bool = False) -> "AuthResult[Self]": ...
```

### Generated DDL

For the `User` model at the top of this document, `User.access_ddl()` returns:

```sql
DEFINE TABLE OVERWRITE user SCHEMALESS
  PERMISSIONS FOR select, update WHERE id = $auth.id;

DEFINE ACCESS OVERWRITE account ON DATABASE TYPE RECORD
  SIGNUP ( CREATE type::thing('user', $email) SET email = $email, password = crypto::argon2::generate($password), name = $name )
  SIGNIN ( SELECT * FROM user WHERE email = $email AND crypto::argon2::compare(password, $password) )
  DURATION FOR TOKEN 15m, FOR SESSION 12h;
```

The `CREATE` target follows the model's `primary_key`, because the rest of the ORM does: with
`primary_key="email"` the record must land at `user:ada@example.com`, not at a random id, or
every later `User.objects().get(email=…)` would address a record the signup never wrote. So the
clause renders `CREATE type::thing('<table>', $<pk>)` when a primary key is configured, and a
plain `CREATE <table>` (server-generated id) when there is none.

The `DEFINE TABLE` is emitted **by default**, and that is deliberate rather than convenient.
Without `FOR select WHERE id = $auth.id`, signin succeeds and `$auth` is set, yet `info()`
silently returns nothing — v0.16.0's spec calls this "the single sharpest gotcha of this
feature". A model-level API that promises to hand back an instance cannot afford to walk into
it, so the permission ships with the access method. `with_table=False` opts out for callers who
manage the table themselves (a `SCHEMAFULL` table, or permissions beyond self-access).

The SIGNUP `SET` clause covers every non-computed field except `id` — the primary-key field
included, since it is a real column the SIGNIN clause has to match on. A field the caller omits
is bound as `NONE`, so optional fields stay optional.

`auth.py` stays I/O-free. Putting the mixin there would have been circular —
`connection_manager` already imports `auth` for `AuthTokens` / `build_auth_payload` /
`wrap_auth_error`, and the mixin must import `connection_manager`. The new module is a leaf:
`model_auth` → `connection_manager` → `auth` → `exceptions`, with `model_base` imported only
under `TYPE_CHECKING`.

## Acceptance criteria

1. `User.access_ddl()` renders the two statements above; `overwrite=False` drops `OVERWRITE`,
   `with_table=False` drops the `DEFINE TABLE`, and the config keys (access name, identifier,
   password field, algorithm, durations) are all honoured — verified without a server.
2. `await User.define_access()` applies cleanly on **8001 and 8002**, and is idempotent: calling
   it twice in a row succeeds.
3. `await User.signup(email=…, password=…, name=…)` returns an `AuthResult` whose `.user` is a
   `User` instance with a populated id and the submitted field values, and whose `.tokens.access`
   is a non-empty JWT.
4. `await User.signin(email=…, password=…)` returns the same record's instance; a wrong password
   raises `SurrealDbAuthenticationError` on both lines (the underlying SDK error differs:
   `NotFoundError` on 3.x, `InternalError` on 2.6.x).
5. `await User.authenticate(token)` returns the `User` instance for that token; a malformed or
   expired token raises `SurrealDbAuthenticationError`.
6. **Isolation** — after a full signup + signin + authenticate cycle, the shared connection is
   still the identity `set_connection()` established: a root-only statement (`INFO FOR DB;`) still
   succeeds through `SurrealDBConnectionManager.get_client()`, and
   `get_session_token()` is unchanged. This is the load-bearing test of the whole design.
7. `bind=True` additionally adopts the token into the shared session, so
   `SurrealDBConnectionManager.get_session_token()` becomes the new token and later ORM calls run
   as that record user.
8. A table without self-select permission (`with_table=False` against a restrictive table) makes
   signin raise a `SurrealDbAuthenticationError` that **names the missing permission**, instead of
   returning `None` or an empty instance.
9. `with_refresh=True` renders `WITH REFRESH` and `FOR GRANT`; `define_access()` and `refresh()`
   work on 3.x and are skipped on 2.6.x. A spent refresh token is rejected (rotation).
10. Calling an auth method with no connection configured raises the usual
    `ValueError("Connection not been set.")` before any socket is opened.
11. `repr(AuthResult(...))` contains no JWT.
12. `ruff format --check`, `ruff check`, `mypy src/` clean; coverage ≥ 70 %.
13. `examples/v0.17.0_model_auth.ipynb` executes top-to-bottom against 8001 with saved outputs.
