# Testing

Test data factories and the pytest plugin.

## 41. Test data factories (`ModelFactory`, `Faker`) and the pytest plugin

Since v0.40.0 `surreal_orm_lite.testing` has the full SurrealDB-ORM's `ModelFactory` and `Faker`: a Factory Boy-style
class declares a model's test data — `Faker` providers, static values and server-side `SurrealFunc` expressions —,
`build()` makes instances without a database and `create()` saves them through the model's own `save()`. An opt-in
pytest plugin, `surreal_orm_lite.testing.pytest_plugin`, gives each test a fresh in-memory database through its
`surreal_db` fixture. Nothing to install: no new dependency, and pytest is needed only for the plugin.

### Declare and use a factory

```python
import random

from surreal_orm_lite import BaseSurrealModel, SurrealFunc
from surreal_orm_lite.testing import Faker, ModelFactory, embedded_database


class Player(BaseSurrealModel):
    id: str | None = None
    name: str
    email: str
    age: int
    role: str = "player"
    tags: list[str] = []
    token: str | None = None  # a server value: the field needs a default


class PlayerFactory(ModelFactory[Player]):
    class Meta:
        model = Player

    name = Faker("name")
    email = Faker("email")
    age = Faker("random_int", min=18, max=80)
    role = "player"  # a static value, copied for each instance
    tags = ["new"]
    token = SurrealFunc("<string> rand::uuid::v7()")  # generated by the server on create()


player = PlayerFactory.build()  # no database
assert player.get_id() is None and player.token is None and 18 <= player.age <= 80
admins = PlayerFactory.build_batch(3, role="admin")  # an override wins
assert [admin.role for admin in admins] == ["admin"] * 3

async with embedded_database():  # a fresh, empty in-memory database
    alice = await PlayerFactory.create(name="Alice")
    assert alice.get_id() is not None and alice.token  # the server's UUIDv7
    await PlayerFactory.create_batch(4)
    assert await Player.objects().count() == 5

random.seed(7)
first = PlayerFactory.build()
random.seed(7)
assert PlayerFactory.build().model_dump() == first.model_dump()  # the same values again
```

A factory names its model in `class Meta: model = …`. `ModelFactory[Player]` types `build()` and `create()` as
`Player`; a plain `class PlayerFactory(ModelFactory)` works too, typed as `BaseSurrealModel`. Each public class
attribute is a declaration:

- a `Faker` gives a new value for each instance;
- a `SurrealFunc` is generated by the server on `create()` (see below);
- any other value — a string, a number, a list, a `datetime`, a `Decimal`, an `Enum`, a `RecordID`, a nested model —
  is a static value, deep-copied for each instance, so two instances never share a list.

Methods, nested classes, `classmethod`s, `staticmethod`s and properties are not declarations. Any other callable
(`datetime.now`, `functools.partial(…)`) is refused with `TypeError` at the `class` statement: lazy values are not
supported yet, so pass such a value at the call.

- `build(**overrides)` returns an unsaved instance; no database, no signal.
- `build_batch(count, **overrides)` returns `count` of them, each with fresh values.
- `create(**overrides)` builds an instance and saves it with `save()`: signals, the model's connection or the active
  `using()` block, query-cache invalidation and an edge's `INSERT RELATION` apply as for any `save()`. It returns the
  saved instance, with its id and the server's values; what `save()` raises propagates unchanged.
- `create_batch(count, **overrides)` calls `create()` `count` times, one record after the other: a failing record
  stops the batch and the records already created stay. For one `INSERT` and no signal, use
  `Player.objects().bulk_create(PlayerFactory.build_batch(100))`.

An override replaces the declaration of that field for the call, and a `Faker` passed as an override is generated.
`count` is positional (`build_batch(3)`), so a model field named `count` stays overridable: `build_batch(3, count=5)`.
A `count` that is not an `int` (or is a `bool`) raises `TypeError`, a negative one `ValueError`, and `0` returns `[]`.

### Faker providers

| Provider       | Value                                                  | Keywords (default)            |
| -------------- | ------------------------------------------------------ | ----------------------------- |
| `name`         | `"<First> <Last>"`                                     | none                          |
| `first_name`   | a first name                                           | none                          |
| `last_name`    | a last name                                            | none                          |
| `email`        | `"<first>.<last><3 digits>@<domain>"`                  | none                          |
| `random_int`   | an `int` from `min` to `max`, both included            | `min` (0), `max` (100)        |
| `random_float` | a `float` from `min` to `max`, rounded to 4 decimals   | `min` (0.0), `max` (1.0)      |
| `text`         | words joined by spaces, cut to `max_length` characters | `max_length` (200)            |
| `sentence`     | 5 to 12 words, capitalized, ending with `.`            | none                          |
| `word`         | one word                                               | none                          |
| `uuid`         | a version-4 UUID, as a `str`                           | none                          |
| `boolean`      | `True` or `False`                                      | none                          |
| `date`         | a `date` from the last 365 days                        | none                          |
| `datetime`     | an aware UTC `datetime` from the last 365 days         | none                          |
| `choice`       | one of `items`                                         | `items` (required, not empty) |

The providers, their pools and their formats are the full ORM's. A `Faker` checks its provider and keywords when it is
built: `Faker("nme")` raises `ValueError("Unknown Faker provider: 'nme'")`, `Faker("random_int", minimum=1)` raises
`TypeError` and names the accepted keywords, and `Faker("choice")` without `items` raises `ValueError`. `choice` keeps
a copy of its `items`, as a list.

### Server-generated values (`SurrealFunc`)

A `SurrealFunc` attribute ([section 15](models.md#15-server-side-values-surrealfunc--server_values)) is SurrealQL the server
evaluates: `create()` passes it to `save(server_values=…)`, so SurrealDB computes the value — `rand::uuid::v7()`,
`rand::int(18, 80)`, `time::now()` — and each record of a batch gets its own. `build()` leaves the field out, so the
model's default applies: the field must have one (`token: str | None = None`). A `SurrealFunc` passed to `build()`
raises `TypeError`; a plain value passed for a `SurrealFunc` attribute is sent as data.

`SurrealFunc` attributes are for node factories. An edge's `save()` is a guarded `INSERT RELATION`, which cannot
evaluate server expressions: a `SurrealFunc` declared on (or inherited by) an edge factory raises `TypeError` at the
`class` statement, and one passed to an edge factory's method raises `TypeError` before any request. Give an edge
field a server value with `DEFINE FIELD … DEFAULT` on the edge table, or declare a plain value or a `Faker`.

### Names and checks

A declaration or an override names a field by its Python name or by its column — an alias
([section 20](models.md#20-field-aliases-server_fields-and-mergerefreshfalse)), an edge's `in`: `password = …` and
`password_hash = …` both set `password`, and a subclass's declaration replaces its parent's under either name. Use one
form per field: both in one class body, or in one call, raise `TypeError`.

Names are checked early, because a model drops an unknown keyword silently: a declared name that is not a field of the
model raises `TypeError` at the `class` statement, listing the fields, and an unknown override raises `TypeError` at
the call — unless the model accepts extra fields (`extra="allow"`). `Meta.model` must be a `BaseSurrealModel`
subclass.

A factory without a model is a base that shares declarations: its methods raise `ValueError`, and the subclass that
sets `Meta.model` checks the inherited declarations against its model. A subclass whose own `class Meta:` does not
set `model` keeps its parent's.

### Reproducible data

Every provider draws from Python's `random` module, `uuid` included: after `random.seed(n)` a factory gives the same
values again (the first example shows it). pytest-randomly reseeds `random` before each test and prints the seed it
used; run `pytest --randomly-seed=N` with that seed to get the same data again.

### Edges, fixtures, transactions and connections

```python
from datetime import date

from surreal_orm_lite import BaseSurrealEdge, SurrealDBConnectionManager
from surreal_orm_lite.testing import SurrealFixture, fixture


class Follows(BaseSurrealEdge):
    since: date | None = None


class FollowsFactory(ModelFactory[Follows]):
    class Meta:
        model = Follows

    since = Faker("date")


@fixture
class Team(SurrealFixture):
    captain = PlayerFactory.build(id="captain", name="Ada", role="captain")
    rookie = PlayerFactory.build(id="rookie")


async with embedded_database():
    async with Team.load() as team:
        edge = await FollowsFactory.create(in_=team.rookie, out=team.captain)
        assert edge.get_id() is not None and isinstance(edge.since, date)
        async with SurrealDBConnectionManager.transaction() as tx:
            await PlayerFactory.build(id="sub").save(tx=tx)
        assert await Player.objects().count() == 3
```

An edge factory takes its endpoints at the call, as `in_` (or `in`) and `out`: a saved instance or a `RecordID`.
`build()` gives a `SurrealFixture` its templates, each loaded as a fresh copy
([section 26](embedded.md#26-embedded-engine-and-test-fixtures)). In a transaction, build and save with `tx=`: `create()` takes no
`tx=`. On a named connection ([section 30](connections.md#30-multiple-databases-add_connection-using)), `create()` inside
`SurrealDBConnectionManager.using("archive")` writes to that database, as `save()` does.

### The pytest plugin

Enable it in the root `conftest.py`, or with `pytest -p surreal_orm_lite.testing.pytest_plugin`:

```python
pytest_plugins = ["surreal_orm_lite.testing.pytest_plugin"]
```

```python
import pytest


@pytest.mark.asyncio  # not needed with asyncio_mode = "auto"
async def test_signup(surreal_db):
    await PlayerFactory.create_batch(2)
    assert await Player.objects().count() == 2
```

It needs pytest and pytest-asyncio (1.0 or later); without pytest-asyncio, loading it raises an `ImportError` that
says so. Nothing in `surreal_orm_lite` imports it, so the library never loads pytest on its own. It gives two
fixtures:

- `surreal_db`: a fresh, empty embedded database for the test — `embedded_database(surreal_db_url)` around it, on the
  current connection, namespace and database `test` — and the previous settings back after it. Function scope; the
  event loop scope is pytest-asyncio's default. `surreal_db` yields `None`, not the client: pytest keeps a fixture's
  value until after its teardown, and an in-process engine stops only once nothing refers to its client. A test that
  needs raw SurrealQL calls `await SurrealDBConnectionManager.get_client()`.
- `surreal_db_url` is `"mem://"`; override it in a conftest for an on-disk database. A server URL fails the test's
  setup with `embedded_database()`'s `ValueError`.

```python
import pytest


@pytest.fixture
def surreal_db_url(tmp_path):
    return f"surrealkv://{tmp_path}/db"
```

It works in pytest-asyncio's strict mode (tests marked `@pytest.mark.asyncio`) and in auto mode, and registers nothing
else (no hook, no marker, no option). It is the `surreal_db` recipe of section 26, shipped.

### Security

- The factories build no SurrealQL: values reach the server through `save()`, as bound data.
- A `SurrealFunc` attribute is SurrealQL you write, inlined by `save()`: never build one from user input (section 15).
- `random` is not a cryptographic generator: `Faker` values, `uuid` included, are **test data, never secrets or
  tokens**. For an id generated by the server, declare `SurrealFunc("rand::uuid::v7()")`.
- The plugin opens embedded engines only: a test run cannot wipe a server's database through `surreal_db`.

### Server lines

Factories behave the same on SurrealDB 3.x, 2.x and the embedded engine: `build()` needs no database and `create()` is
the model's `save()`, `SurrealFunc` attributes included. `surreal_db` is an embedded database, which answers as a 2.x
server (core 2.3.10). The [2.x/3.x table](compatibility.md#orm-behaviour-surrealdb-2x-vs-3x) and the
[embedded table](compatibility.md#orm-behaviour-the-embedded-engine) hold their rows.

### Coming from the full SurrealDB-ORM

- **Any static value is collected**: a `datetime`, a `Decimal`, an `Enum`, a `RecordID` or a nested model is
  deep-copied for each instance, where the full ORM keeps only primitives and containers and drops the rest silently.
- **Typed factories**: `ModelFactory[Player]` types `build()` and `create()` as `Player`; the full ORM's unparametrized
  `ModelFactory` still works, typed as `BaseSurrealModel`.
- **`SurrealFunc` attributes** (an addition of this library): generated by the server on a node factory's `create()`,
  left out by `build()`.
- **Mistakes fail early**: a `Faker` checks its provider and keywords when it is built, a factory its names at the
  `class` statement and the overrides at the call, with `TypeError` for a name that is no field, where the full ORM
  raises at the first value and passes unknown names to the model, which drops them.
- **`uuid` follows `random.seed()`**: it draws from `random`, where the full ORM calls `uuid.uuid4()`.
- **The pytest plugin is opt-in**: `pytest_plugins` or `-p`, no entry point and no extra to install; the full ORM has
  no `surreal_db` fixture.
- **`create_batch()` saves one record at a time**, as in the full ORM, with signals and server values per record;
  `bulk_create(build_batch(n))` is the one-`INSERT` path.
- **A `Faker` override is generated**, where the full ORM hands the `Faker` object itself to the model.
- **`count` is checked**: `TypeError` for a non-`int` or a `bool`, `ValueError` for a negative count, `[]` for `0`;
  the full ORM returns `[]` for a negative count.
- **`surreal_db` yields `None`**, not the client, so that no test keeps the engine alive past its teardown.
- **No `Sequence`, `LazyAttribute` or `SubFactory`** (the full ORM has none either): a callable attribute such as
  `datetime.now` is refused at the `class` statement rather than stored as a value, so a later version can give it a
  lazy meaning.
- **`Meta.model` is inherited**: a subclass whose `class Meta:` does not set `model` keeps its parent's, as in
  Factory Boy, where the full ORM raises `ValueError`.
- **`cls` and `count` are positional-only**: a model field named `count` (or `cls`) stays overridable —
  `build_batch(3, count=5)` —, where the full ORM raises `TypeError: got multiple values for argument 'count'`. Only
  the keyword form `build_batch(count=3)`, which no full-ORM example uses, stops working, and Factory Boy names the
  batch argument `size` anyway.
- **No `SurrealFunc` on an edge factory**: `TypeError` at the `class` statement or at the call, since an edge's
  `INSERT RELATION` cannot evaluate it; use `DEFINE FIELD … DEFAULT` on the edge table.
- **Names are brought to the Python field name**: a field is declared or overridden by its Python name or its column,
  one form per field, where the full ORM passes names as written and loses an override given under the field's other
  name.
